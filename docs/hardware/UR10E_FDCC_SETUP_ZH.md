## 2. 仿真和真机候选的关系

仿真 Python FDCC 来自 SliceIt 所用的控制器修改版；现场候选用同源 ROS1 C++
代码与项目补丁。相同工具链、坐标和名义参数已经对齐，30个连续输入的关节
输出最大差约1.33e-15 rad。测试调用实际 C++ 控制器和 IK solver，
不是另写一套公式互相验证。具体证据和未覆盖项见 TAMSCAGE。

同一个平台内，策略、SAC、WM+MPPI和解析MPC都经共享动作映射器与FDCC执行。
解析MPC内部的粗略FDCC预测、学习WM预测和真实执行层是三件事；
不能把同源执行控制律解释成预测模型或真实机器人动力学完全相同。

对齐候选未加载进活动UR驱动，原有 /homeL/dong/ur10e_fdcc_ws 未被替换。
不存在“已经把新控制器烧录到UR控制箱”的操作。

## 3. 坐标、力与去皮

候选使用 knife_control 控制点、ati_sensing_frame 测量点和
knife_compliance 柔顺参考系。六关节按名称重排，不能直接使用反馈数组顺序。
目标位姿在机器人基座系；力/力矩必须同时核对轴向和取矩点。

当前仿真 wrench 来自机器人内部作用与材料反力的计算，在虚拟 ATI 测量点
换算、滤波、去皮后进入 FDCC；它不是实物 ATI 数据流。
当前砧板仅作几何防穿透，读数不含尚未实现的板面反力。

传感器清零和 FDCC 工具重力基准必须在同一静止姿态同步建立。
FDCC 应处理姿态变化带来的重力变化，避免采集端和控制器重复补偿。
仿真 reset 与解析MPC预测的两处去皮错误均已修复：
前者使用正确传感器系重力和重心力矩，后者固定使用物理控制器的去皮基准。
这不等于现场 ATI 已完成清零/标定。

保留的负载估算来源：
- IKEA 刀 0.170 kg 是用户确认净重，不是从商品包装栏推断。
- PLA 刀架 147.323 cm³、法兰 89.392 cm³；暂用实心密度1240 kg/m³，
  估重0.182681 kg与0.110846 kg。打印填充率、壁厚和真实质量未测。
- 刀惯量按均匀 CAD 分布缩放到170 g；ATI 惯量按91.7 g、45×15.7 mm包络估计。
- 当前估计法兰总负载0.555227 kg；ATI测量截面下游刀和刀架0.352681 kg。
  这两种负载口径不能混用。称重和多姿态补偿应覆盖这些估计值。
- 保留来源UR10e连杆惯性，不按整机商品重量统一缩放。
- 传感器安装角和运动学仍需实物轴标识/本机标定核对；名义模型不是已标定真机。


## 4. 真机验证顺序

1. 只读关节、TF、外置ATI，核对坐标、单位、时间戳、下游负载与无接触残差。
   完成 TCP/板面和工具安装核验。
2. 离线回放真实输入，检查动作映射、逐轴控制输出和参数范围。
   候选参数上限与仿真对齐只说明接口不会静默裁剪，不代表真机已许可最大刚度。
3. 在线影子运行：只计算不下发，记录消息年龄、周期和超时处理。
   动作映射每50 ms调用一次，不能每个底层伺服周期重复累计偏移。
   在线参数和目标需要对应同一次动作，生效时刻尚未实测。
4. 由现场人员完成无刀/无刃工具的小范围空中轨迹和停止测试，再验证轻触响应。
   目标从当前实测位姿初始化；检查单一命令控制器、数据过期和通信中断处理。
5. 通过后再接上层规划或策略。真实接触后持续读取受力，不复制仿真的几何投影
   或过去的冻结读数。食材切割和完整闭环需单独记录结果。

先用确定的参考目标测试FDCC，可排除MPC预测误差的干扰；
再用解析MPC做接口/影子运行。修复后的MPC不是已经完成真机时序验收的启动入口。
继续上层接入见 [控制与MPC交接](UR10E_MPC_HANDOFF_ZH.md)。

安装/校准结果写入 TAMSCAGE，材料、摩擦和信号辨识方法写入 REAL2SIM；
不要在本页重复现场状态或新增另一份安装报告。
