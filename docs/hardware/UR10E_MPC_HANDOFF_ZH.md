## 接口：目标、测量、动作

- 目标 g 是基座坐标系下的控制参考点目标位姿，加目标速度：
  [x,y,z,qx,qy,qz,qw,v_target]。位置 m、速度 m/s，四元数顺序必须保持一致。
  视觉给出的切面/刀尖目标需要先通过真实安装变换换算为控制参考点目标。
- 反馈包括关节 q/qd、带时间戳的六维 ATI 力/力矩，以及映射器/控制器和任务历史。
  力单位 N、力矩 N·m；明确读数所在坐标系和力矩取矩点。
  不把纯 MPC 的输入说成仅有 8 维目标，也不要求给它食材的仿真真实状态。
- MPC 输出与当前策略共用的六维动作：两项刚度、两项控制增益、
  沿刀方向偏移、可选倾角。当前倾角禁用；随后经动作映射器和 FDCC 生成机器人指令。
  这些动作不是六维关节力矩，也不是预测力直接发给机械臂。
- 真机适配需要从测量和命令历史构造规划状态，明确队列采样顺序、延迟、
  当前任务计数和几何板面标志。不能拿仿真特权状态或冻结旧传感器读数填空。
- 在当前累计到位规则下保留到位计数；不要擅自换成首次到位即结束。
  几何板面约束没有砧板反力模型，不能据此声称已验证真机触板响应。

## 现场分阶段接入

1. 先只读盘点控制电脑 Ubuntu/ROS、UR PolyScope/IP/运动学标定、
   ATI 采集接口与序列号标定、Nano 准确型号与 SDK 版本。
   按 FDCC 文档建立关节反馈、ATI 原始与补偿后反馈、TF。
2. 完成 TCP/刀具安装、ATI 力/力矩坐标、负载质量/重心与时间同步验证。
   仿真 PLA/CAD 惯性是估算，真机参数需测量；重力补偿避免重复执行。
3. 先用人工确认的目标完成底层 FDCC 的空载/无刃接触验证，再接规划器。
   ROS 控制器默认不自动激活运动；目标由当前实测位姿初始化，避免跳到仿真初始姿态。
4. 用录制的真机状态离线跑 MPC，再做只计算不下发的在线影子运行。
   记录规划耗时、数据年龄、动作与目标；核对坐标、动作映射、超时处理。
5. 通过时序和底层控制检查后，现场人员执行空中轨迹，再按 FDCC 文档逐步验证接触。
   训练服务器上的仿真结果不能替代这一步。停止后仍持续读取真实受力。
6. 加视觉：刀具停在扫描区域外 → 采集点云 → 算切面和起刀/最终目标 →
   核对可达性与接近路径 → 刀移动到起刀位 → MPC 闭环切割。
   当前设计只在切割前扫描，不要求持续视觉跟踪；若接近时物体被碰动，原目标应重新核验。

### 时序是尚未完成的一项

当前任务控制间隔为 50 ms。已有八候选小测试中，纯 MPC 规划中位耗时
约 0.489–0.511 s/世界/指令，超过该间隔；正式 512 候选的规划时延未单独量出。
材料仿真每步耗时不等于规划器耗时。
必须在实际控制电脑上测规划耗时分布和最坏数据延迟，FDCC 底层周期单独确认。
如需降低规划频率、异步执行或改变规划设置，应明确新时序/保持方式并验证，
不能静默套用现有 50 ms 假设或把过时指令排队发送。

## Nano：眼在手外标定

相机固定在外部支架，机器人和相机基座相对不动时，采用 eye-to-hand。
求 T_base_camera，使 p_base = T_base_camera * p_camera。
这里 camera 是 SDK 输出点云的实际坐标系，不是 CAD 外壳原点。

[Mech-Mind 官方六轴机器人眼在手外标定指南](https://docs.mech-mind.net/en/suite-software-manual/latest/vision-calibration/eth-auto-calib.html)
提供固定相机、机器人末端安装标定板的流程。按现场软件版本选择支持的流程，
不是未经核对就运行自动运动步骤。

需要保存：相机序列号、SDK/固件、点云单位、标定板规格、采集位姿、
T_base_camera、标定残差及独立位置验证结果。
此外单独标定刀尖 TCP/安装变换、砧板平面和 ATI 坐标。
更换食物不需要重新做固定相机外参标定，但需要重新定位食物；
移动相机、机器人基座或其安装后重新核验/标定。
仿真 Nano 外参和光学模型是暂定参数，不能当作真机标定结果。
